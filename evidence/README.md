# Evidence

Everything the claims in the main README rest on, kept together so the root of the repository is
the tool and this is the working out.

Some of it is a board over the author's own folder, published deliberately rather than leaked. That
folder is "brain-ops": a personal operations system of a few hundred markdown files that scheduled
agent prompts read and rewrite every night. It is where every check came from, one check per
failure that had actually happened there. The files below name its contents and counts, because a
claim about catching real failures is worth nothing without the failures it caught.

Nothing here is needed to use the tool. It is here so the claims in the main README can be checked
rather than taken on trust.

| File | What it is |
|---|---|
| `case-study.md` | 29 days of file-backed agents, 125 documented failures. Where the checks come from. |
| `2026-09-06-case-study.html` | The same case study as a page. |
| `board-brain-ops-2026-09-06.txt` | A full board over the author's own folder, 6 September 2026. Node names withheld. |
| `findings-brain-ops-2026-09-06.md` | The same run written up one finding at a time, each with the defect the check descends from. |
| `protocol.md` | The validation protocol, fixed before any result existed: what counts as a true positive, a false positive, a miss. |
| `prospective-ledger.md` | The running result of the 28-day self-test, 7 September to 5 October 2026. Filled nightly. |
| `simulation/` | Four rounds of user simulation, 6 to 7 September 2026, and what each round changed. |

`protocol.md` was written before the self-test started, on purpose. It says what would count as a
failure of the tool, so that the ledger cannot be read generously after the fact.
