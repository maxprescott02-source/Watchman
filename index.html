Watchman.

It tells you the next morning when one of your scheduled jobs quietly stopped updating the file you rely on.

v0.2.0 · one command to install · reads a folder, writes a file

The failure it is built for

Not a job that crashes. You find out about those. This is the job that runs, finishes, reports success, and leaves yesterday's file behind it.

What you see

$ tail -1 runs.log
2026-09-11 03:00 nightly ok, 2.1s

$ launchctl list | grep nightly
0  com.you.nightly   (loaded)

Green. The scheduler fired, the job exited clean, the log line is there.

What is actually true

$ head -1 summary.md
Summary as at 2026-09-08

# three days ago. Nothing said so.

One step inside the job skipped itself and wrote the skip somewhere nothing reads. Every job that opens the summary tomorrow trusts it.

A scheduler that says healthy is not evidence. The file the job touches is. Watchman checks the file.

What you get

It runs once a night over the folder your jobs write into, and leaves one plain file at the top of it. That is the whole product. There is no dashboard to open and nothing to log into.

WATCHMAN.md a real one
Last checked: 2026-09-11 06:02 UTC+10 - new: inbox-summary ran at 06:01 but inbox-summary.md still says 2026-09-04. The job ran without updating its output; check what it wrote and where. - ongoing (since 2026-09-09): ledger-sync left no evidence for its Thu 11 Sep 07:00 run. It may not have run, this machine may have been asleep, or it may have run without updating runs.log. Check the job. If it is safe to rerun, run it now.
full board: .watchman/last-board.txt

One line per real problem, not one per check that noticed it. Every line ends in the thing to do. When nothing needs you the file stays where it is and says Healthy: nothing needs you., because a file that disappears looks like a tool that died.

Can you use it?

Three questions. The first one decides it.

01

Do you have jobs that run on a schedule and leave a file behind?

A nightly summary, a report, a ledger, an export, a line appended to a log. Two to ten of them is the shape this was built for. Claude Cowork tasks, ChatGPT Work, a cron job, an n8n flow: it does not care what wrote the file.

YesThis is for you. It works from the files themselves, so nothing in your jobs has to change.
NoThen skip it. It will install, say healthy every night, and never tell you anything.
02

Can you run one command in a terminal, once?

That is the entire setup. It reads the folder, works out what your jobs look like, writes its own config, and schedules itself. Anything it had to guess can only ever warn, never fail, until you confirm it.

YesAbout fifteen minutes to the first useful line, most of it waiting.
NoThere is a version you paste into Cowork as a scheduled task instead.
03

Mac, Linux, or Windows?

Only the nightly scheduling differs. The checking is identical everywhere.

Mac or LinuxIt schedules itself and tells you it read the schedule back.
WindowsEverything works, but there is no automatic nightly run yet. You start it yourself.

What it is not

  • Not a tracing or eval tool. Those inspect what happened inside a run. LangSmith, Langfuse and Braintrust do it well. Watchman looks at the state a run left behind, which is what the next run trusts.
  • Not a dashboard. Nothing to check. It only speaks when something needs you.
  • Not a service. No account, no server, no telemetry. Nothing leaves the machine.
  • Not a framework. Pure Python standard library, no dependencies, one config file in the folder it watches.

Start

FOLDER is the folder your jobs write into.

$ python3 -m watchman install FOLDER
  1. It reads the folder and proposes the config itself, asking you nothing.
  2. It prints the board so you see what it found before you trust it.
  3. It schedules the nightly run and only says it is done once it has read the schedule back.
  4. You read WATCHMAN.md at the top of the folder each morning. Nothing else.

Built September 2026. It is currently running a 28 day self test over the folder it was written for, and the results get published whatever they show.
